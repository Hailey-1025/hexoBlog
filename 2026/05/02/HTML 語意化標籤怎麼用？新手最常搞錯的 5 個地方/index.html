HTML 語意化標籤怎麼用？新手最常搞錯的 5 個地方

發表於 2026-05-02 更新於 2026-05-03 分類於 HTML/CSS
整理 HTML 語意化標籤的常見錯誤與正確用法，幫助新手建立正確的網頁結構觀念。

前言

在剛開始學 HTML 時，多數人都會習慣用 <div> 把所有內容包起來。
但當專案變大、結構變複雜時，你可能會開始遇到這些問題：

  • HTML 結構難以閱讀
  • SEO 表現不佳
  • 螢幕閱讀器無法正確解析內容

這時候，「語意化標籤（Semantic HTML）」就不只是語法，而是結構設計能力。

什麼是 HTML 語意化？

HTML 語意化（Semantic HTML）指的是使用「有意義的標籤」來描述內容結構，而不是單純用 <div> 排版。

👉 目標很簡單：讓「人」與「機器（搜尋引擎、輔助工具）」都能理解你的頁面。

❌ 錯誤 2：把 <section> 當萬用容器

很多人會把 <section> 當成有語意的 <div>

👉 問題：

  • 沒有標題 → 幾乎等於 div
  • 結構不清楚

✅ 正確用法：

👉 重點：<section> 通常應該要有標題。但有例外——如果是獨立功能區塊（像是搜尋結果列表、地圖元件），即使沒有標題也可以使用 <section>，因為沒有更具體的標籤來代替它。

❌ 錯誤 3：搞不清 <article> vs <section>

這是最多人卡住的地方。

👉 記一個最簡單判斷：

  • 可以獨立存在、拿去別的地方也成立 → <article>
  • 只是頁面或文章的某個分段 → <section>

👉 <article> 可以被拿去別的地方使用（像 RSS 訂閱、文章列表），拿出來單獨看也有完整意義。

💡 還有一點新手容易忽略：兩者可以互相嵌套。

  • <article> 裡面可以有多個 <section>（一篇文章分成多個段落）
  • <section> 裡面也可以有多個 <article>（一個評論區裡有多則留言）

❌ 錯誤 4：濫用 <nav>

有些人會把任何「有互動的東西」都放進 <nav>。

👉 常見誤用情境：

👉 <nav> 應該只用於網站主要導航（全域選單、頁尾選單等），分頁（pagination）或上一篇 / 下一篇連結屬於輔助導航，建議用 <section> 包起來，或加上 aria-label 區分。

❌ 錯誤 5：亂用 <main>

👉 <main> 有幾個重要限制：

  • 一個頁面只能有一個 <main>
  • 不應該放在 <header>、<footer>、<nav>、<article>、<aside> 裡

✅ 正確結構：

👉 <main> 代表「這頁最重要的內容」，搜尋引擎和螢幕閱讀器都會優先解析它。

我到底該用哪個標籤？

快速判斷：

  • 主內容 → <main>
  • 導覽 → <nav>
  • 獨立內容（可單獨存在） → <article>
  • 區塊分段（頁面的一部分） → <section>
  • 補充資訊（不影響主內容） → <aside>
  • 頁首 / 頁尾 → <header> / <footer>
  • 如果只是為了排版或樣式，沒有語意 → 用 <div>

🧩 常見但容易忽略的語意標籤

  • <aside>：補充資訊，例如推薦文章、作者資訊、廣告區塊。注意：不一定要放在側邊位置才能用，重點是「內容與主體沒有直接關係」。
  • <time>：日期時間
  • <mark>：重點標記
  • <figure> + <figcaption>：圖片與說明文字

⚠️ <hgroup> 已較少使用，不建議使用

總結

語意化標籤不是「把 div 換名字」而已。

👉 重點是：

  • 讓結構更清楚
  • 讓搜尋引擎看得懂
  • 讓程式碼更好維護

如果你只是把 <div> 換成 <section>，其實沒有比較好。

真正的差別在於：你有沒有在「設計結構」

如果你之前也是「div 切天下」，那這篇應該會幫你釐清不少觀念。
