函式陳述式（Function Declaration）

✅ 函式陳述式有 Hoisting

「Hoisting（提升）」是 JavaScript 的一個特性：函式陳述式會在程式執行前先完成建立，因此可以在宣告之前呼叫。

JavaScript 引擎在實際執行程式碼前，會先建立執行環境，把函式陳述式全部「登記好」，所以呼叫寫在宣告之前也沒關係。

💡 補充：Hoisting 並不是真的把程式碼搬移到最上面，而是 JavaScript 引擎在「建立執行環境」的階段就預先處理了函式陳述式。理解這一點，有助於之後學習 Execution Context 的概念。

函式表達式（Function Expression）

❌ 函式表達式無法在宣告前呼叫

函式表達式是透過變數保存的，因此是否能提前呼叫，取決於變數的提升行為：

const / let 進入 TDZ（暫時性死區） ❌ ReferenceError
var 提升但值為 undefined ❌ TypeError

立即執行函式（IIFE）

定義完馬上執行，不需要另外呼叫：

💡 IIFE 之所以要用 () 把函式包起來，是因為 JavaScript 解析器（parser）看到 function 開頭時，會將其視為「函式陳述式」——而陳述式必須有名字，也不能直接執行。

用 () 包住後，函式會變成一個會產生值的表達式，其值就是該函式本身，因此後面才能接著用 () 立即呼叫。

這是 Expression vs Statement 最經典的應用之一：刻意把陳述式轉換成表達式。

總結

當你開始能分辨「哪些程式碼是在產生值，哪些是在控制程式流程」，你會發現 JavaScript 很多看似神奇的行為，其實都有跡可循——Hoisting 的邏輯、IIFE 為什麼需要括號、框架裡各種奇特的寫法，背後都和這個概念有關。

理解了 Expression / Statement 和 Hoisting 之後，你已經具備往下深挖的基礎了，紮穩基礎，後面學習的東西就會越來越清晰。
