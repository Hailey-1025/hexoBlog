JavaScript DOM 事件完整指南：addEventListener、事件冒泡與事件委派

發表於 2026-05-18 分類於 JavaScript
深入學習 JavaScript 的 DOM 操作與事件監聽，從 createElement、addEventListener 到事件冒泡、鍵盤偵測，透過實際範例一步步掌握網頁互動開發的核心技巧。

前言

當你點擊按鈕、送出表單、切換選單時，背後其實都是 JavaScript 的 DOM 事件機制在運作。

從最基本的 click 事件，到進階的事件冒泡（Event Bubbling）與事件委派（Event Delegation），都是前端開發中非常核心的概念。

本篇文章將透過實際範例，帶你一步步理解 JavaScript 如何監聽使用者操作，並打造具有互動效果的網頁。

createElement：安全新增 HTML 元素

上一篇提到了 innerHTML 的使用，這邊想再補充另一個：document.createElement() 用來動態建立新的 HTML 標籤，是比 innerHTML 更安全的寫法。

innerHTML vs createElement 的差異

方法 行為 安全性
innerHTML 先清空內容，再寫入 較低（可能受 XSS 攻擊）
createElement 保留原始 HTML，僅新增節點 較高

addEventListener：註冊事件監聽

addEventListener 是 JavaScript 中綁定事件最常用的方式，使用時需搭配 DOM 元素，並帶入兩個參數：

  • 第一個參數：要監聽的事件類型（如 click、mouseover）
  • 第二個參數：事件觸發時執行的 function

常見滑鼠事件

  • click：單擊
  • dblclick：雙擊
  • mouseover：滑鼠移入

如何確認 DOM 的事件監聽狀態

在 Chrome 開發者工具中，可以透過以下步驟檢視元素是否有綁定事件：

  1. 開啟 DevTools（F12）
  2. 選取 Elements 面板，點擊目標元素
  3. 切換到右側的 Event Listeners 分頁

即可看到該元素上所有已註冊的事件監聽器。

event 物件：取得當下元素資訊

當事件觸發時，callback function 會自動接收一個 event 物件（通常縮寫為 e），其中記錄了當下事件的所有資訊。

常用屬性

屬性 說明
e.clientX / e.clientY 相對於瀏覽器視窗的座標
e.pageX / e.pageY 相對於整個網頁的座標
e.target 實際被點擊的元素
e.keyCode 被按下的鍵盤對應數字碼

注意： event 物件只在 function 執行期間存在，執行完畢後資料就會消失。

nodeName：辨識 DOM 節點類型

nodeName 屬性可以回傳目前 DOM 元素對應的 HTML 標籤名稱（大寫），方便開發者確認目前操作的是哪種元素。

這在事件委派（Event Delegation）的情境中特別實用。

e.target：精確定位點擊元素

e.target 記錄的是實際被點擊到的 DOM 元素，在監聽較大範圍的容器時非常有用。

e.target 搭配 nodeName 實戰應用

結合 e.target 與 nodeName，可以精準判斷使用者點擊到哪種標籤，實現 事件委派（Event Delegation） 的效果。

情境：只有點到按鈕（INPUT）才執行事件

這個模式的優點是：只需要在父元素上綁定一個事件，就能統一處理所有子元素的互動，減少重複的事件綁定，也有助於效能優化。

preventDefault：取消預設行為

某些 HTML 元素有內建的預設行為，例如：

  • <a> 標籤會跳轉連結
  • <form> 的 submit 按鈕會送出表單並重新整理頁面

使用 e.preventDefault() 可以阻止這些預設行為，讓你自行控制後續邏輯。

Event Bubbling 與 Event Capturing

JavaScript 的事件傳遞分為兩個階段：

Capturing（捕獲階段）

事件從最外層的父元素開始，由上往下傳遞到目標元素。

Bubbling（冒泡階段）

事件從目標元素開始，由下往上冒泡傳遞到最外層的父元素。

預設情況下，addEventListener 是在冒泡階段觸發事件。若要改為捕獲階段，可傳入第三個參數 true：

stopPropagation：中止冒泡事件

當內外層元素都有監聽同一事件時，點擊內層元素會同時觸發外層的事件（冒泡效應）。使用 e.stopPropagation() 可以阻止事件繼續向上冒泡，避免監聽互相干擾。

keyCode：偵測鍵盤輸入

透過 e.keyCode（或現代瀏覽器建議的 e.key），可以偵測使用者按下了哪個按鍵。

常見 keyCode 對照

按鍵 keyCode
Enter 13
Escape 27
空白鍵 32
上 / 下 / 左 / 右 38 / 40 / 37 / 39

💡 建議： 目前多數新專案都已改用 e.key，除非需要相容非常舊的瀏覽器，否則不建議再使用 keyCode。

常見監聽事件整理

事件 說明
click 滑鼠點擊事件
input 每當使用者在輸入框中輸入、刪除或修改內容時觸發
keydown 使用者按下鍵盤按鍵時觸發，常用於快捷鍵、遊戲控制或表單驗證
change 表單元素的值改變後觸發，通常會在失去焦點後執行
mousemove 滑鼠在元素範圍內移動時持續觸發，常用於拖曳、座標追蹤或互動特效
mouseover 滑鼠移入元素時觸發
mouseout 滑鼠移出元素時觸發
focus 元素取得焦點時觸發
blur 元素失去焦點時觸發

blur 與 focus：焦點事件

表單輸入框有兩個常用的焦點事件：

  • focus：使用者點進輸入框時觸發
  • blur：使用者離開輸入框時觸發

這兩個事件常用於即時驗證表單內容。

網頁座標系統：screen、page、client

在滑鼠事件中，可以透過 event 物件取得座標資訊，但這三種座標的參考基準不同：

座標 參考基準 說明
screen 實體螢幕 依螢幕解析度計算，不受瀏覽器視窗影響
client 瀏覽器視窗 相對於當前可見的瀏覽器畫面範圍
page 整個網頁 包含捲動距離，相對於整個頁面原點

從父元素監聽子元素

利用事件冒泡的特性，可以在父元素上統一監聽子元素的事件，搭配 e.target.nodeName 來篩選目標，不符合條件時用 return 中斷執行。

這個技巧稱為 Event Delegation（事件委派），特別適合用在動態新增的子元素上，因為動態新增的元素無法預先綁定事件，但透過監聽父元素就能輕鬆處理。

總結

本篇整理了 JavaScript DOM 事件操作的核心概念：

  • createElement：安全地新增 HTML 元素
  • addEventListener：綁定各種使用者互動事件
  • event 物件：取得事件當下的詳細資訊
  • e.target / nodeName：精確識別被操作的元素
  • preventDefault：攔截並自訂預設行為
  • 事件冒泡 / 捕獲：理解事件傳遞機制
  • stopPropagation：防止事件層層觸發
  • 事件委派：統一從父元素管理子元素的事件

掌握這些概念後，你就能開始打造各種具備豐富互動體驗的網頁了！
