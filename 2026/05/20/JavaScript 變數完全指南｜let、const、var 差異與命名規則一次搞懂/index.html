JavaScript 變數完全指南｜let、const、var 差異與命名規則一次搞懂

發表於 2026-05-20 分類於 JavaScript
搞不清楚 let、const、var 的差別嗎？這篇文章從變數宣告方式、命名規則到作用域，用白話文帶你一次釐清，附常見地雷與實用範例，JavaScript 新手必看！

「變數」是所有程式語言的基礎，而 JavaScript 光是宣告變數就有三種方式。如果你曾被 let、const、var 搞得一頭霧水，這篇文章就是為你寫的 🙌

基礎理解

什麼是變數？

你可以把變數想像成一個貼了標籤的盒子。盒子裡放著值（數字、文字、布林等），標籤就是你取的名字，之後可以透過這個名字來取用或修改裡面的東西。

變數命名規則

取一個好名字不只是風格問題，錯誤的命名直接讓程式爆掉。以下是你一定要知道的規則：

硬性規則（違反就報錯）

  • ❌ 不可以數字開頭：1price → 錯誤，price1 → OK
  • ❌ 不可使用 JS 保留字：像 let、function、class 這些 JS 自己在用的詞，不能拿來當變數名
  • ✅ 英文、數字、_、$ 都可以用
  • ✅ 有區分大小寫：price 和 Price 是不同的兩個變數

let：會變動的值

當這個變數的值會在程式執行過程中改變，就用 let。

const：不應該被修改的值

當這個值不應該被修改的時候，用 const。用 const 可以明確告訴其他開發者「這個值不應該被改動」，減少意外 bug。

var：已被淘汰的寫法

var 是 JavaScript 早期的宣告方式，因為設計問題，已逐漸被 let 和 const 取代。

var 的問題：

  1. 可以重複宣告：同名變數宣告兩次不報錯，容易造成意外覆蓋
  2. 函式作用域（非區塊）：if、for 裡面宣告的 var，在外面也看得到
  3. 提升（Hoisting）：在宣告之前就使用不報錯，而是得到 undefined，難以除錯
  4. 汙染全域：會自動掛在 window 物件上

作用域（Scope）快速理解

作用域決定了「哪裡可以看到這個變數」，記住三個層級就夠：

  • 全域：整個程式都看得到
  • 函式：只有 function 裡看得到，函式執行結束後就消失
  • 區塊：{} 裡才看得到（let / const 適用）

進階理解（面試加分）

作用域鏈（Scope Chain）

當 JavaScript 在當前作用域找不到變數時，會一層一層向外（父層）尋找，直到找到為止。

重點：內層可以看見外層，但外層看不見內層。 這能有效防止變數污染，確保程式碼模組化。

暫時性死區（Temporal Dead Zone, TDZ）

很多人誤以為 let 和 const 不會提升（Hoisting），這其實是常見誤解。它們會提升，但行為與 var 完全不同：

  • var：執行前會同時完成「宣告」與「初始化」，所以宣告前讀取得到 undefined
  • let / const：執行前已被建立（提升），但尚未初始化，必須等到執行到宣告那行才可存取

在「進入區塊」到「完成初始化」之間的這段時間，就是暫時性死區（TDZ）。 在 TDZ 內存取變數會直接報錯：
