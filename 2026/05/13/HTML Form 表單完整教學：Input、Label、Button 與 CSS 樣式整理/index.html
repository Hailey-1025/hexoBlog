HTML Form 表單完整教學：Input、Label、Button 與 CSS 樣式整理

發表於 2026-05-13 分類於 HTML/CSS
深入淺出介紹 HTML Form 表單、Input 各種屬性用法及 CSS 樣式優化建議，幫助新手快速掌握前端開發中的表單設計要點。

前言

無論是登入頁、註冊頁、搜尋框，甚至購物車結帳流程，都離不開 HTML 表單（Form）。雖然表單看起來只是幾個 input 與 button 的組合，但實際開發時，會牽涉到：

  • 欄位語意化
  • 無障礙設計（Accessibility）
  • 行動裝置鍵盤體驗
  • 表單驗證
  • 瀏覽器相容性
  • CSS 樣式統一

本文從 HTML Form 的基礎結構開始，整理常見 Input 類型、Label 用法，以及實務開發中不可忽略的注意事項。

注意事項

  • 瀏覽器相容性：不同瀏覽器對表單元素的預設樣式可能略有差異，開發時需特別注意排版與互動一致性，或可搭配 Bootstrap、Tailwind CSS 等 UI 框架協助統一樣式。。
  • 原生樣式限制：date 與 select 的樣式受瀏覽器與作業系統影響，難以用純 CSS 完全統一。若專案對 UI 一致性要求較高，建議使用 Flatpickr 或 Select2 等第三方套件。

Form、輸入欄位、Submit

Form

form 表單的兩個核心屬性：

  • action：指定資料提交的目標位置（通常是後端 API）
  • method：指定 HTTP 請求方法
    • POST：用於提交資料（如註冊、登入），資料不會顯示在 URL
    • GET：用於取得資料（如搜尋），資料會帶在 URL 參數中（安全性較低，適合搜尋場景）

Input

使用 input 必須搭配對應的 label（詳見 Label 章節）。

常用屬性：

屬性 說明
type 輸入欄位的種類
name 欄位名稱（後端接收資料時的 key）
value 欄位的值，表單送出時會作為資料提交給後端
placeholder 提示文字（不可取代 label，詳見 FAQ）
required 指定為必填欄位
readonly 僅可閱讀，不可輸入
disabled 鎖定欄位，不可使用也不會被提交

Type 種類：

使用正確的 type，在 mobile 裝置才會彈出對應鍵盤。

例如 type="text" 與 type="tel" 在電腦上無明顯差異，但在行動裝置上分別會彈出中文鍵盤與數字鍵盤。

文字輸入類：

  • text：一般文字輸入

    • 搭配 inputmode="numeric" 可讓手機瀏覽器自動彈出數字鍵盤

  • email：電子郵件（瀏覽器會驗證格式）

  • tel：電話號碼

  • password：密碼輸入（文字會隱藏）

  • number：數字輸入

    ⚠️ 實戰建議：type="number" 仍可輸入 e、- 等特殊符號，且不同瀏覽器行為不一致，手機輸入體驗也較差。實務上更推薦：

    再搭配 JavaScript 做格式驗證。

日期時間類：

  • date：日期選擇器

    ⚠️ 實戰建議：各瀏覽器樣式不同且難以自訂，有高度客製化需求時建議使用 Flatpickr 等套件。

選擇類：

  • radio：單選按鈕（同組選項的 name 必須相同才能實現單選效果）
  • checkbox：多選框（即使 name 相同也支援多選）

按鈕類：

  • submit：提交表單
  • button：一般按鈕（需搭配 JS 使用，點擊不會觸發表單提交）
  • reset：重置表單

其他常用欄位：

  • select：下拉式選單，內含多個 option
  • textarea：多行文字輸入（可用 CSS 設定寬高）
    • rows：可輸入行數
    • cols：每行可輸入字元數

Label

Label 是表單無障礙設計的核心，讓螢幕閱讀器能正確識別表單欄位。

  • for 屬性：連結到對應 input 的 id，點擊 label 可自動聚焦到輸入欄位（擴大點擊範圍）
  • 最佳實踐：id 和 name 通常使用相同名稱，方便管理

為什麼需要 Label？

  • 提升使用者體驗（擴大點擊範圍）
  • 支援螢幕閱讀器（無障礙設計）
  • 符合 HTML 語意化標準

Button

Button 元素建議明確指定 type 屬性，有三種類型：

  • submit：送出表單
  • button：一般按鈕，用於 JS 操作
  • reset：重置表單

這是很多新手造成表單意外送出的常見原因！

<input type="submit"> 是 HTML 原生提交方式，但現在多半改用 <button type="submit"> 以獲得更好的樣式彈性與可讀性。

差異：Name vs Value vs Label

屬性 用途 範例
label 顯示給使用者看的文字 “電子郵件”
name 表單提交時的欄位名稱（後端接收資料的 key） name="email"
value 實際傳送到後端的值（資料的 value） value="user@example.com"

📝 這些都是 HTML 的屬性（attribute）。

表單驗證屬性

HTML5 提供了內建的表單驗證屬性，可在不使用 JavaScript 的情況下做基本驗證：

屬性 說明
required 必填欄位
maxlength 最大輸入字元數
minlength 最小輸入字元數
max / min 數值或日期的最大/最小值
pattern 正規表達式驗證

⚠️ 前端驗證只能提升使用者體驗，真正的資料驗證仍需由後端再次檢查。

💡 HTML 內建驗證適合快速實作，但完整專案仍建議搭配 JavaScript 做更細緻的錯誤提示與自訂邏輯。

表單常用 CSS 設定

基本樣式屬性

  1. border - 邊框
  2. color - 文字顏色
  3. border-radius - 圓角
  4. background - 背景
  5. padding - 內距
  6. font-size - 字體大小
  7. width - 寬度
  8. cursor: pointer - 游標變手指（按鈕常用）

互動狀態

  • :hover - 滑鼠移入
  • :focus / :focus-visible - 取得焦點（正在輸入）
  • :active - 點擊當下

實用技巧

⚠️ 無障礙提醒：避免直接使用 outline: none 移除焦點樣式，這會讓純鍵盤使用者無法辨別目前聚焦的欄位。建議改用 :focus-visible 並自訂樣式，既保留無障礙體驗，又能統一視覺設計。

常見問題 FAQ

Q：placeholder 可以取代 label 嗎？

不可以。placeholder 是提示文字，使用者開始輸入後就會消失，無法幫助使用者確認欄位用途。螢幕閱讀器也不一定能正確讀取 placeholder。label 才是語意化且無障礙的正確做法。

Q：disabled 和 readonly 有什麼差異？

disabled readonly
使用者能輸入 ❌ ❌
表單提交時會送出 ❌ ✅
CSS :disabled 偽類 ✅ ❌

Q：GET 和 POST 怎麼選？

  • GET：適合「查詢」，資料帶在 URL，可書籤化（例：搜尋）
  • POST：適合「提交」，資料在請求體中，不顯示在 URL（例：登入、註冊）

Q：要不要關閉 autocomplete？

視情況而定。一般欄位（姓名、email）建議保留，方便使用者自動填入。密碼管理欄位或一次性驗證碼欄位可加上 autocomplete="off" 或 autocomplete="one-time-code"，不過部分瀏覽器（如 Chrome）可能仍會自動填入登入資訊。。

結語

HTML Form 雖然是前端最基礎的元素之一，但實際開發時往往會結合 API 串接、表單驗證、無障礙設計、響應式排版與使用者體驗（UX）。熟悉表單的設計方式，能大幅提升網站的可用性與互動品質。

當你開始接觸 Vue、React 等框架時，也會發現所有表單處理的核心概念，其實都建立在原生 HTML Form 之上。打好基礎，走得更遠。
