傳值 vs 傳址（重要！）

這是很多人一開始搞不懂，然後寫出奇怪 bug 的根源之一。

原始型別：傳值（複製一份）

物件型別：傳址（共用同一個記憶體位置）

⚠️ 陣列和物件是「傳址」，兩個變數會指向同一份資料。如果你不想互相影響，需要做「拷貝」，例如用展開運算子 [...arr] 或 JSON.parse(JSON.stringify(obj))。

作用域（Scope）

作用域決定了「一個變數在哪裡可以被存取到」。

核心規則

  • 內層可以存取外層的變數
  • 外層不能存取內層的變數
  • 不同作用域之間是獨立的

var 的函式作用域 vs let/const 的區塊作用域

💡 這就是為什麼現代 JS 推薦用 let 寫 for 迴圈，用 var 的話變數會「跑出來」變成全域，很危險。

詞法作用域（Lexical Scope）

變數的作用域在程式碼「寫好的時候」就決定了，不是執行的時候才決定。

屬性 vs 變數

重點整理：

  • 屬性（Property）可以被 delete 刪除
  • 變數（Variable）不能被 delete 刪除
  • 永遠記得宣告變數，不要讓它意外變成全域屬性！

提升（Hoisting）

JavaScript 在執行程式碼前，會先經歷一個「創造階段」，把變數和函式宣告都「提升」到作用域的最頂端。

let / const 的暫時性死區（TDZ）

let 和 const 也有提升，但在宣告前存取會直接報錯，而不是給你 undefined。

這個「宣告前的禁區」就叫做暫時性死區（Temporal Dead Zone, TDZ），是 let/const 刻意設計的保護機制，讓你的錯誤更早被發現。

undefined vs not defined

這兩個看起來像但完全不同，一定要分清楚：

undefined not defined
原因 宣告了但沒賦值 根本沒有宣告
是否報錯 ❌ 不報錯 ✅ 報錯（ReferenceError）
程式是否繼續 ✅ 繼續執行 ❌ 後面的程式碼全部停止

⚠️ not defined 的紅字錯誤是「阻斷性錯誤」，會讓後面所有程式碼都無法執行，一定要修！
