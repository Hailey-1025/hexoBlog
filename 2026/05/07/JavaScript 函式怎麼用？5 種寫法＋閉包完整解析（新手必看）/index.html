JavaScript 函式怎麼用？5 種寫法＋閉包完整解析（新手必看）

發表於 2026-05-07 分類於 JavaScript
從函式陳述式、函式表達式、箭頭函式、立即函式，到閉包（Closure），完整解析 JavaScript 函式的各種寫法與差異，搭配 hoisting、this 綁定的實例說明，幫助新手建立完整觀念。

前言

JavaScript 的函式（Function）是所有程式邏輯的核心，不論是事件處理、資料轉換，甚至是框架（如 React、Vue），都大量依賴函式運作。

但對新手來說，常見的困惑是：

  • function 跟箭頭函式差在哪？
  • 為什麼有些函式可以先呼叫，有些不行？
  • closure（閉包）到底在幹嘛？

這篇文章會從最基本的函式寫法開始，帶你一步步理解：

  • 函式陳述式、函式表達式、箭頭函式的語法差異
  • this 與 hoisting 的行為比較
  • 立即函式（IIFE）的用途
  • 最重要的閉包（Closure）概念與實戰用法

幫你建立一個完整的 JavaScript 函式觀念。

快速選擇：我該用哪一種函式？

如果你只是想快速知道怎麼選，可以先看這裡：

  • 一般函式定義 => 用「函式陳述式」
  • 需要重複使用的邏輯 => 用「函式陳述式」
  • 當作回呼 / 搭配陣列方法 => 用「箭頭函式」
  • 需要使用 this => 用「function」
  • 想保留狀態 => 用「閉包」

不確定時，預設使用箭頭函式（現代主流寫法）

函式陳述式（Function Declaration）

函式陳述式是最傳統的函式定義方式。

特性：Hoisting（提升）

JavaScript 引擎在執行前會先掃描整份程式碼，將函式陳述式整個提升到作用域頂端，因此不管呼叫放在宣告前面還是後面，都能正常執行。

函式表達式（Function Expression）

函式表達式是將一個匿名函式賦值給變數。

特性：Hoisting 行為不同，留意 TDZ

這裡要稍微說清楚一點，「函式表達式不會被提升」這句話其實不夠精準：

  • 變數宣告本身會被提升，但值（函式）不會
  • 使用 const / let 宣告時，存取提升前的變數會遇到 TDZ（暫時性死區，Temporal Dead Zone），直接拋出錯誤

縮寫規則

箭頭函式可以根據情況進一步縮寫：

1. 單一回傳值：省略大括號與 return

2. 單一參數：省略括號

5. 回傳物件字面值：需用括號包住

⚠️ 箭頭函式與 this（重要！）

箭頭函式沒有自己的 this，它的 this 是在定義時就決定了，繼承自外層作用域，而不是在呼叫時動態決定。

因此，箭頭函式不適合用在以下情境：

  • 物件方法（需要 this 指向物件本身）
  • constructor 建構函式
  • 需要動態 this 的事件處理器

在 DOM 事件中，this 通常指向觸發事件的元素，因此不建議使用箭頭函式（除非你是刻意要使用外層的 this）

立即函式（IIFE，Immediately Invoked Function Expression）

立即函式在定義後會立刻執行，通常用來建立獨立的作用域，避免污染全域變數。

使用時機

在 ES Modules（import / export）出現之前，IIFE 是常見的模組化手法，用來隔離作用域、避免全域污染。

現代專案已有更好的替代方案，IIFE 目前較少使用，除非：

  • 維護舊專案（非模組環境）
  • 需要快速隔離某段初始化邏輯

閉包（Closure）

閉包是指一個函式記住並存取其被定義時的作用域，即使外部函式已執行完畢，內層函式依然能存取那些變數。

每次呼叫 counter()，都能存取並修改 makeCounter 作用域內的 count，這就是閉包的核心。

前端實戰範例：UI 狀態切換

這種寫法常出現在：

  • UI 狀態控制（展開 / 收合、顯示 / 隱藏）
  • React Hooks 的底層概念（useState 本質上也是閉包）

⚠️ 閉包常見陷阱：迴圈 + 非同步

原因是 var 沒有區塊作用域，三個 callback 共享同一個 i，等 setTimeout 執行時 i 已經是 3 了。

解法一：改用 let（最簡單）

解法二：用閉包鎖住每次的 i

IIFE 在這裡的作用就是為每次迴圈建立獨立的作用域，讓每個 callback 各自保有自己的 i。

閉包的特性與注意事項

  • 閉包讓函式可以保有私有狀態，是實作模組化的基礎
  • 每次呼叫外層函式，都會建立全新的閉包環境
  • 過度使用閉包，可能導致變數長期被參考而無法被垃圾回收，需留意記憶體效能。
  • 只要閉包內的變數仍被引用，就不會被垃圾回收（Garbage Collection）

總結

如果你是剛入門的前端工程師，建議先牢牢掌握這三件事：

  1. 函式陳述式 vs 箭頭函式的差異（語法 + hoisting）
  2. this 的動態 vs 靜態行為（一般函式 vs 箭頭函式）
  3. 閉包的基本概念（保有狀態、工廠函式）

當你能夠熟練運用 JavaScript 的 arrow function、closure（閉包）、以及理解 this 綁定的時機，你就已經跨過「初學者 → 初階工程師」的重要門檻。這些觀念在寫框架、處理 API、或做資料轉換時，會頻繁出現。

函式不只是一個語法，而是 JavaScript 思維的核心。

另外函式也可以作為參數傳遞，或作為其他函式的回傳值，這種用法稱為高階函式（Higher-Order Function），是閉包概念的進一步應用，會在下一篇文章介紹。

如果你已經理解這篇內容，建議下一步可以深入：

  • this 綁定（call / apply / bind）
  • 高階函式（Higher-Order Function）
  • 非同步函式（async / await）

這些都是現代前端開發的核心技能。
