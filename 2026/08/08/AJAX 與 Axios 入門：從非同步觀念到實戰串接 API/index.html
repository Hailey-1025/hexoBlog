AJAX 與 Axios 入門：從非同步觀念到實戰串接 API

在現代網頁開發中，前端經常需要與後端伺服器交換資料，卻不希望因為等待資料而讓整個網頁「卡住」。這正是 AJAX 技術存在的意義。這篇文章會從 AJAX 的基本觀念出發，介紹如何使用 Axios 套件串接 API，並深入理解 JavaScript 的非同步程式設計方式。

什麼是 AJAX？

AJAX 全名為 Asynchronous JavaScript and XML，是一種讓網頁能夠在不重新載入整個頁面的情況下，透過 JavaScript 與伺服器進行非同步資料交換的技術。

「非同步程式設計」則是更廣泛的程式設計概念，不只 AJAX 才會使用，例如計時器、檔案讀取等操作也都屬於非同步的範疇。

雖然 AJAX 名稱裡有 XML，但現今大多數的請求傳輸的資料格式都是 JSON，XML 已經較少被使用。

Axios 是什麼？

Axios 是一個以 Promise 為基礎的 HTTP 用戶端函式庫，可以在瀏覽器或 Node.js 環境中發送 HTTP 請求。它提供較方便的 API，並支援攔截器、自動處理 JSON 等功能。

.then / .catch / .finally 的鏈式寫法

Axios 是基於 Promise 設計的，因此可以用「鏈式寫法」（chaining）串接多個處理步驟：

  • .then() 代表「接著執行」，可以連續加上多個 .then()
  • 實務上通常需要處理請求失敗的情況，可以使用 .catch() 捕捉 Promise 的 rejection；有些專案也會改用 async/await 搭配 try/catch 統一處理錯誤
  • .finally() 會在 Promise settled（不論成功或失敗）後執行，通常適合用來處理必要的收尾工作，例如關閉 loading 狀態

執行順序整理如下：

情境 執行順序
請求成功 .then → .finally
請求失敗 .catch → .finally

HTTP 請求方法（HTTP Method）

AJAX 發送請求時會依賴不同的 HTTP 方法，每種方法代表對伺服器資料不同的操作意圖：

  • GET（獲取）：從後端取得資料，通常用於請求資源，不會更動伺服器上的資料，適合查詢或讀取資訊。
  • POST（新增）：提交資料到後端，通常用於建立新資源或送出表單，資料會放在請求的 body 裡。
  • PUT（更新）：修改後端資料，用於更新整筆資料的內容。
  • PATCH（局部修改）：修改後端資料的部分內容，只更新資料中特定欄位，而非整筆覆蓋。
  • DELETE（刪除）：刪除後端指定的資源。

更完整的方法說明可以參考 MDN - HTTP 請求方法。

HTTP 狀態碼（Status Code）

狀態碼是用來判斷前後端在傳遞資料的過程中，請求是否成功的代碼：

  • 2XX 系列：請求成功
    • 200 OK：請求成功
    • 201 Created：請求成功，並且建立了新的資源，常見於 POST 請求成功建立資料時
  • 3XX 系列：重新導向
  • 4XX 系列：Client 端發生錯誤
    • 401 Unauthorized：未通過身分驗證，例如 Token 過期或沒有提供有效的登入憑證
    • 403 Forbidden：已通過身分驗證，但沒有權限存取該資源
    • 404 Not Found：伺服器找不到所請求的資源，路徑寫錯是常見原因之一，但不是唯一原因
  • 5XX 系列：Server 端發生錯誤

執行結果會發現，最後一行 console.log(data) 印出的是空陣列。發送非同步請求後，JavaScript 不會因為等待伺服器回應而阻塞後續程式碼的執行；等伺服器回應完成後，Promise 才會進入對應的狀態，.then() 中的內容也才會在後續的執行流程中被處理。

常見的非同步操作情境包括：

  • 網路請求
  • 計時器（如 setTimeout）
  • 檔案讀取

控制非同步程式碼的執行順序

當專案中有多個非同步操作，而且彼此有先後順序關係時，就需要更完整的方式來控制流程。以下介紹三種常見寫法。

1. Callback（回呼函式）

最原始的做法，是把「下一步要做的事」當作參數（函式）傳入，等目前的非同步操作完成後再呼叫它：

這種寫法雖然可行，但如果非同步操作一多，就會出現層層嵌套的情況，也就是俗稱的 回呼地獄（callback hell），程式碼會變得難以閱讀與維護。

2. Promise

Promise 改善了 callback 的可讀性問題，透過 .then() 與 .catch() 來處理非同步操作的結果，並可以用鏈式呼叫來管理多層非同步流程。Promise 有三種狀態：pending、fulfilled、rejected。執行非同步操作時，可以透過 resolve() 表示成功，或透過 reject() 表示失敗。

三種寫法的比較整理如下：

寫法 優點 缺點
Callback 概念簡單、直接 多層嵌套時難以閱讀（回呼地獄）
Promise 可鏈式呼叫，結構清楚 多個 .then() 仍稍嫌冗長
async/await 程式碼最接近同步寫法，易讀好維護 需搭配 try/catch 處理錯誤
