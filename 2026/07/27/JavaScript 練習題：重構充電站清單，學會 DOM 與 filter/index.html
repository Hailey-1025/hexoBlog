JavaScript 練習題：重構充電站清單，學會 DOM 與 filter

發表於 2026-07-27 分類於 JavaScript
以「充電站清單」練習題為例，示範如何重構一段新增／篩選資料的程式碼，並延伸整理 DOM 操作、filter、高階函式與閉包等 JavaScript 核心觀念。

前言

很多 JavaScript 入門練習都會做到「新增資料 + 篩選清單」，看似只有幾十行程式碼，其實背後會用到 DOM 操作、事件監聽、陣列方法，甚至還能延伸到高階函式與閉包等重要觀念。

這篇文章會以「充電站清單」為例，從最初版本開始，一步步重構程式碼，最後整理這個練習中涉及的 JavaScript 核心知識。

題目說明

  1. 提供表單，輸入充電站名稱、選擇付費方式，按下「儲存」後新增到清單。
  2. 清單下方有三個篩選按鈕：全部／免費／投幣式，點擊後只顯示符合條件的資料。

一開始的實作大致長這樣：資料存在 data 陣列中，透過 str 這個字串變數累加要顯示的 HTML，再交給 addData() 統一塞進畫面：

這段程式碼可以正常動作，但按照嚴重程度排序，有五個問題值得改進：

  1. 渲染邏輯重複：初始渲染（initialInformation）與篩選渲染各自寫了一次幾乎相同的迴圈與拼字串邏輯。
  2. str 是全域可變狀態：篩選、新增資料都直接疊加或重設同一個字串變數，邏輯容易互相干擾，難以預期目前畫面顯示的到底是什麼。
  3. 迴圈中重複呼叫渲染函式：initialInformation 每跑一次迴圈就呼叫一次 addData()，等於畫面被重新整理了 4 次，明明只需要 1 次。
  4. 事件綁定位置不對：btn.addEventListener 被包在 newData() 函式裡，其實只需要在最外層綁定一次即可。
  5. 沒有防呆機制：使用者可以送出空白名稱，產生沒有意義的資料。

JavaScript 練習題：重構充電站清單

延伸複習：相關的 JavaScript 觀念

在整理這次程式碼時，也順便複習了一些平常很容易忘記、但和這個案例息息相關的 JavaScript 基礎知識，整理成筆記如下。

1. querySelector 家族與元素集合

這題用 querySelector 取得表單與清單元素（.list、.filter、.stationName 等），這裡順便複習一下常見的元素選取方式：

  • querySelector：只取第一個符合條件的元素。
  • querySelectorAll：取出所有符合條件的元素，回傳 NodeList。

querySelectorAll() 和 element.childNodes 都會回傳 NodeList，不過 childNodes 會包含文字節點（例如標籤之間的換行、空白），而 querySelectorAll() 只會回傳符合選擇器條件的元素節點，兩者不能直接畫上等號。

如果改用 getElementsByClassName 這類方法，取出來的則是「HTMLCollection」，同樣不是真正的陣列，使用陣列方法前常常需要先轉成陣列：

在這篇的 renderData() 中，就是利用 filter() 篩選出符合條件的充電站，再交給 map() 產生對應的 <li> HTML 字串，這也是取代最初版本手寫 if / else 判斷的關鍵。

6. 閉包（Closure）：把 data 包起來

MDN 對閉包的定義是：閉包是函式以及該函式被宣告時所在的作用域環境的組合，白話一點說就是「內部函式可以持續存取外部函式的變數」。

閉包常見的三個特性：

  1. 重複調用：每次呼叫回傳的函式，都能延續上一次的狀態。
  2. 獨立變數：不同次呼叫，會產生各自獨立、互不影響的變數。
  3. 隱藏變數：外部無法直接存取或修改，只能透過回傳的函式間接操作。

小結

這次的練習題雖然功能單純，但完整走過一輪後，會發現背後牽涉的觀念其實不少：從 DOM 選取、filter、高階函式，到表單處理與閉包，都是前端開發日常會不斷用到的基礎。

很多面試常見的 Todo List、購物車、留言板，其實都是同一種思考模式，只是資料結構越來越複雜而已。把這類小題目真正理解，比一直背語法更能提升 JavaScript 實力。

下一步可以試著把這題再進階：加入「編輯」「刪除」功能，把 data 包成閉包模組限制存取方式，或是改成存在 localStorage，讓重新整理頁面後資料還能保留，都是很好的延伸練習方向。
